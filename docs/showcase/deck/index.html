01EA Healthcare

A healthcare platform, built end to end.

  • For patients.
  • For doctors.
  • For the front desk.
EA Healthcare is a full-stack platform for patients, doctors and a hospital front desk: fifteen services, a React app, and everything running locally.

02Appointments

Book in a few taps.

  • Choose a doctor.
  • Pick a day and a slot.
  • Get reminded automatically.
Slots have a capacity set by the doctor, booked counts are live, and a full slot is refused by the server. Reminders go out on their own.

03Doctors

Doctors run their own day.

  • Set each day: in person, video or off.
  • Announce a delay in one step.
  • Join the video visit.
Doctors choose in-person, telemedicine or off per shift, set the capacity, announce delays, and join calls from their dashboard.

04Video visits

Video visits, no vendor.

  • Open the link.
  • The server checks the window.
  • Peer to peer, encrypted.
The server decides who may join and when. Video then flows peer to peer over WebRTC, with signalling through the browser, so no video service is needed.

05Health report

A report that reads the whole record.

  • It reads the treatment history.
  • Finds two similar, anonymised cases.
  • Writes the report on the server.
Similar cases are found by keyword overlap and anonymised. A local rule-based analyst writes three sections: overview, comparable outcomes and outlook. No cloud model is involved.

06Community

A community that teaches.

  • Share and ask.
  • Read what doctors write.
  • Articles and first aid.
Patients post updates and feedback, doctors publish articles and first-aid guides, admins post FAQs. Comments and reactions work on every post.

07Search and libraries

Find anything.

  • Search the whole platform.
  • Look up 40 medicines.
  • Browse 12 pieces of equipment.
One search fans out to patients, doctors, medicines, appointments and posts. The medicine and equipment libraries are public.

08Languages

Ten languages.

  • English
  • বাংলা
  • हिन्दी
  • العربية
  • Español
  • 日本語

Served from an offline dictionary.

Every interface string is translated per user from a dictionary shipped with the app, so it works offline. Ten languages, 330 stored translations.

09Offline

Works with no internet.

  • No email provider.
  • No SMS gateway.
  • Codes arrive in a local mailbox.
There is no email, SMS or push provider. Messages go to a local outbox shown on a mailbox page, so one-time codes work on a plane. Only the optional translator uses the internet.

10Front desk

The front desk, in control.

  • Approve doctors.
  • Assign rooms.
  • Read the statistics.
Admins approve doctors, allocate rooms, book walk-in patients, manage users, and read operational statistics.

11Made true

Made true.

  • Any signed-in user could deactivate accounts.Now admins only.
  • Doctor passwords were stored in plaintext.Hashed once, in one place.
  • The AI report crashed on every call.It works on copies.
  • Video join window was inverted.5 minutes before to 20 after.
  • A render loop flooded the browser.One request per string.
  • Mock data looked like real data.Wired to the services.
  • Six cloud services, keys in source.Zero cloud dependencies.
Seven real defects found by reading the code and running every screen as each role. Each has a real fix and is covered by the end-to-end suite.
