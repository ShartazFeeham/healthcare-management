P1Authorization rules matched no routescriticalResolved
Symptom
Any signed-in patient could deactivate or suspend any account, and the internal e-mail lookup answered anonymous callers.
Root cause
Route patterns did not match the real paths (two path segments vs three), so requests fell through to “authenticated”. A broad permitAll listed before the internal-only rule also swallowed it.
Fix and guard
Patterns corrected, the specific rule moved ahead of the broad one. Verified: a patient now gets 403, an admin 200, anonymous getEmail 403.

P3The AI report crashed on every callhighResolved
Symptom
“Internal call to AI analysis failed” for every patient with a treatment record.
Root cause
To anonymise similar cases, the code changed ids on managed JPA entities. When the request ended, Hibernate tried to write those changes back: “identifier of an instance of Treatment was altered from -1 to 4”.
Fix and guard
Anonymise a detached copy. The managed entity is never touched.

5

Treatment plan

Decisions, not just features.

Chose Local rule-based analyst

Rejected A cloud language model

Because Patient data stays on the server, results are deterministic, it costs nothing and works offline.

Trade-off accepted It cannot reason beyond its knowledge base and templates.

Chose BroadcastChannel signalling

Rejected A signalling server

Because No extra service to run or secure for a demo-grade call.

Trade-off accepted Both participants must use the same browser profile; a real deployment needs a signalling service.

Chose Pre-translated dictionary

Rejected Translating the interface live

Because Ten languages that never fail on a network call.

Trade-off accepted New strings are English until translated or the translator is reachable.

Chose Local mailbox and outbox

Rejected Email, SMS and push providers

Because One-time codes are visible and testable offline.

Trade-off accepted Nothing is actually delivered to a real phone or inbox.
